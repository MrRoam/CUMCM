# CUMCM 2026 B 题协作仓库

本仓库用于全国大学生数学建模竞赛 B 题“无线电干扰源的快速自动定位与清除”的团队协作。项目按“官方输入、探索试验、正式计算、生成结果、论文、提交物”的生命周期组织，目标是让论文中的公式、图表和关键数字都能追溯、复核和重新生成。

## 目录说明

```text
CUMCM/
├─ inputs/
│  ├─ official/B题/   # B 题官方 PDF、Word 附件和论文格式原件，只读保存
│  └─ external/       # 团队自行收集并实际使用的外部数据
├─ experiments/       # 候选模型、探索脚本和一次性试验
│  └─ archive/C题/    # 未选 C 题的历史核验材料，不属于当前主线
├─ src/               # 已整理、已验证、可复现的正式代码
├─ outputs/           # 正式代码生成的图、表和数值结果
├─ paper/             # 唯一权威论文源稿及其引用文件
├─ submission/        # 从冻结 Git 提交生成的最终提交副本
├─ docs/B题/          # B 题 Markdown 转换、材料索引、页面图和建模说明
├─ AGENTS.md          # 稳定协作规则
├─ DECISIONS.md       # 重大技术、模型与口径决策
└─ AI_USAGE.md        # AI 工具使用和人工核验记录
```

各目录遵循以下边界：

- `inputs/official/` 只保存官方原件，不在原文件上清洗、改名或覆盖。
- `docs/B题/` 保存从官方原件提取的可检索 Markdown、页面渲染图和团队分析；这些文件是派生材料，不能替代官方原件。
- `inputs/external/` 只保存建模实际使用的外部数据，并记录来源、获取日期、用途和许可要求。
- `experiments/` 允许快速试错，但试验结果不能直接作为论文正式依据。
- `src/` 是正式计算代码的唯一来源，使用仓库相对路径，并将结果写入 `outputs/`。
- `outputs/` 中用于论文的图、表和数字必须能由代码重新生成，禁止手工篡改生成物。
- `paper/` 只维护一份权威正文，不同时维护 Word 和 LaTeX 两套正式版本。
- `submission/` 是发布区，不在其中直接编辑源码、数据或论文。

## 第一问运行入口

在仓库根目录运行（无第三方依赖）：

```console
python -m src.q1 --demo
python -m src.q1.validate
```

源码与测试位于 `src/q1/`，输出位于 `outputs/q1/`。演示输入均为人工构造，不是官方数据；数值结果与源码哈希对应。普通 JSON 输入格式及算法适用边界见第一问说明。验证通过不代表已经完成人工复核或通过模拟器测试。

## 第二问运行入口

在仓库根目录运行：

```console
python -m unittest src.q2.test_strategy
python -m src.q2 recommend --first-x 0 --first-y 0 --bearing-deg 0 --side left
python -m src.q2 verify-selected
python -m src.q2 search
```

模型契约、适用边界和AI接续顺序见 `src/q2/README.md` 与 `src/q2/strategy_config.json`。当前结果只支持未被目标圆域额外裁剪的标准完整扇形，不构成连续全局最优或模拟器成绩。

## 工作流

```text
inputs → experiments → src → outputs → paper → submission
```

1. 保持 `inputs/official/B题/` 中的官方原件不变。
2. 在 `experiments/` 中比较定位、覆盖、路径规划和调度算法。
3. 团队采纳并验证模型后，将完整实现晋升到 `src/`。
4. 从 `src/` 运行正式计算，把论文采用的图表与数值写入 `outputs/`。
5. 人工检查公式、单位、边界条件、随机种子和关键数字后，再将结果写入 `paper/`。
6. 从一个明确的冻结 Git 提交生成 `submission/` 中的论文与支撑材料。

## Git 协作

- 不直接向 `main` 推送。每项工作从最新 `main` 创建短生命周期分支。
- 一个分支和一次提交只处理一个明确问题。
- 创建 Pull Request 前确认变更完整、相关验证通过、论文与结果一致，并说明剩余风险。
- 修改 Word、Excel 等难以合并的二进制主文件前，先指定当期唯一整合者。
- 不按成员建立私人目录，不使用“最终版_v2”等副本管理版本。

## 完成标准

一项会影响论文结果的工作只有在满足以下条件后才算完成：

- 输入来源、数据口径、参数和模型假设已经说明；
- 正式实现已经从 `experiments/` 晋升到 `src/`；
- 图表和关键数字可从代码重新生成；
- 另一名成员能够复核核心公式、约束和结果；
- 重大选择已记录到 `DECISIONS.md`；
- AI 参与情况及人工核验已按需记录到 `AI_USAGE.md`；
- 变更内容、验证方法和剩余风险已经交代清楚。

稳定执行规则见 [`AGENTS.md`](AGENTS.md)。工具链确定后，再按真实需要增加依赖文件、运行入口以及 `tests/`、`configs/` 等目录。
