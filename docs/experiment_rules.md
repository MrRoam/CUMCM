# 实验目录与产物规范

本规范适用于 `experiments/` 中的候选模型、探索脚本和一次性试验，统一文件位置、运行记录和正式成果衔接。实验设计与结果正文由作者或 AI 根据具体任务组织，不规定章节、表格或固定模板。

## 目录结构

```text
experiments/
├─ README.md                         # 实验索引
└─ E01_q2_method_comparison/          # 一个明确问题对应一个实验目录
   ├─ README.md                      # 实验说明、设计与复现入口
   ├─ run.py                         # 探索代码入口，名称和语言按实际需要
   └─ RESULTS.md                     # 结果解释与证据链接

outputs/
└─ experiments/
   └─ E01_q2_method_comparison/       # 与实验目录同名
      └─ <run-id>/                   # 每次运行独立保存
         ├─ manifest.json            # 实际运行信息
         ├─ metrics.csv              # 数值结果，文件名与格式按实际需要
         └─ figures/                 # 按需生成的图
```

上面的实验名和代码、数值文件是示例，不预建空实验或虚构运行结果。`README.md` 是每个实验的入口，`RESULTS.md` 在有实际结果或失败记录时建立；其他文件按需要创建。配置较多时可增加配置文件，多个脚本可在实验目录内组织，不要求所有实验采用 Python。

## 实验与运行的组织

- 使用现有复数目录名 `experiments/`。已有 `b_adaptive_q3`、`b_benchmark_scale` 等目录保留名称，避免破坏依赖；新实验目录建议采用 `E<编号>_<简短主题>`，例如 `E01_q2_method_comparison`；跨问题的实验不必带问题编号。编号在仓库内唯一，新建前检查已有索引及待合并工作。
- 按需要回答的问题划分实验，不按成员或“最终版”划分。同一目的下的参数变化、随机种子与重复计算通常属于同一实验的不同运行。
- 每次启动使用新的 `run-id`，建议采用时间戳加简短标识；同一实验内不得重名。续跑只有在确实恢复同一次运行时才沿用原目录，并在运行记录中注明恢复信息。
- 探索代码与说明放在 `experiments/<实验目录>/`；生成的数值、图片和运行记录放在 `outputs/experiments/<实验目录>/<run-id>/`。读取官方原件时遵守根目录 `AGENTS.md`，不得就地改写。
- 代码使用仓库相对路径或从代码位置解析仓库根目录。共享文档不写死成员个人电脑路径。

## 文件职责

- `experiments/README.md` 只维护实验索引，给出各实验的目的、进度和说明或结论入口；不复制详细设计和结果数字。索引的具体排版可调整。
- 实验目录的 `README.md` 提供说明、设计和实际可用的复现入口。内容结构由作者或 AI 按实验需要生成，不强制填写统一问题清单。
- `RESULTS.md` 解释本实验的结果，引用具体 `run-id` 与证据文件。正文结构、图表形式和结论组织暂不固定；实验被采纳时，在这里指向正式实现与正式结果。
- 每次运行的 `manifest.json` 保存实际输入及其版本标识、代码版本、参数、执行命令、运行状态和产物位置。优先由运行程序写入，不把计划值冒充实际值；随机实验记录实际种子。暂不制定统一 JSON 字段模板。
- 代码版本应能找回本次执行的内容。已提交代码可记录提交号；使用未提交改动时，同时保存可恢复的差异或相关源码快照，不能只记录提交号或文件哈希。
- 数值和图由代码生成，不手改后作为计算结果。大文件、缓存和环境不因位于输出目录就默认提交到 Git；按需保留获取或重建方式。

## 比较、探索与历史

探索实验可以同时尝试多个因素；声称某一改动带来提升时，应有可比的基线和条件。多个因素一起改变所得结果，只能支持相应组合方案的效果，不能直接归因到单个因素。本规范不把“每次只改变一个变量”作为所有实验的要求。

保留失败运行及其必要证据，不用新结果覆盖旧结果。区分程序完成、结果有效与团队采纳，具体表达方式由实验决定。说明文档更新当前判断，历史运行保留当时的输入、配置和产物；不得通过重写旧记录让历史看起来符合新方案。

当前不引入 `CONTROL.json`，也不新增逐次实验审批流程。确需长任务控制或资源管理时，遵守该任务已有的执行约束。

## 正式成果衔接

实验经团队采纳、整理和验证后，将完整实现整理到 `src/`，由正式入口生成论文使用的图、表和数值，写入 `outputs/` 中明确的正式结果位置，与 `outputs/experiments/` 下的探索结果区分。

在实验结果说明中记录正式代码、正式输出和来源运行的对应关系。保留原实验及必要证据，不把所有日志、缓存和中间产物搬入正式成果。进入论文、提交物及人工核验的要求继续遵守根目录 `AGENTS.md`。
