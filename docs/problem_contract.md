## 4. 干扰源属性和未知信息

1. 问题 3、4 每局共有 10～16 个目标，具体个数未知。问题 3 全部为全向源，问题 4 包括全向和定向源。[B 问题 3—4]

8. 公开四接口未提供指定案例种子、获取真值或重放已结束案例的功能。已读材料没有给出目标位置、有效接收半径、发射方向或测向误差的完整概率分布；本版不补充分布假设。[A1 §4.5；A2 §3、§6—9；B 附录 3—4]

## 5. 测向定义与观测反馈

### 5.1 示向度

在检测点改变接收天线指向，测向机通过场强变化推断目标方向。测得的最大场强方向的方位角称为示向度。角度从 +x 轴逆时针计量：东 0°、北 90°、西 180°、南 270°，范围 [0°,360°)。其指向为“检测点指向源”，不是源的发射朝向。[B 附录 2(1)；A2 §1.2、§2.3]

读数相对真实方位角有误差，题设范围为 [-1°,1°]。同一地点的电磁环境在一段时间内固定，重复检测不会改变误差；不同地点、不同电磁环境下误差才呈现统计规律。题面没有规定独立、零均值、正态或均匀分布。[B 附录 2(1)]

接口的 `svd_deg` 单位为度，保留两位小数并归一化到 [0,360)。只在 `direction` 结果中返回。没有场强或距离数值字段。[A2 §2.3、§7.2—7.3]

### 5.2 一次合法检测的三种结果

| `measure_result` | 含义及条件 | 是否返回角度 | 检测动作本身耗时 |
|---|---|---|---:|
| `no_signal` | 当前点接收不到该频道信号；可能为该频道无未清除源、超过有效接收距离，或处于定向源辐射范围外 | 否 | 5 秒 |
| `near` | 距离源不超过 5 米且在有效辐射范围内，信号过强，无法获得示向度 | 否 | 5 秒 |
| `direction` | 接收到信号且能够获得示向度 | 是，`svd_deg` | 5 秒 |

来源：B 附录 2(5)、(9)；A1 §2.2；A2 §7。

### 5.3 交会定位的题面定义

B 附录 2 图 2 使用两个检测点说明交会定位：每个示向度方向两侧各偏离 1° 的边界限定可能方向范围，重叠部分形成图示红色定位区域。问题 1 要求推广到若干检测点，计算其多边形定位区域的直径。本版仅记录定义，不指定区域构造、直径或圆覆盖算法。

## 6. 光学精确定位与清除

- 距离指定频道的未清除目标不超过 20 米时，光学设备可以精确定位，随后激光清除一定成功。包含 20 米边界。[B 附录 2(8)；A2 §8.2]
- 光学定位耗时 3 秒，成功后激光清除再耗时 2 秒。接口把两步合并为 `/clear`。[A1 §2.3]
- 成功只与清除点到目标的距离有关，与全向/定向类型及定向朝向无关。[B 附录 2(8)；A2 §8.2]
- 每次清除请求只针对其 `channel` 指定的目标，不是同时清除周围所有频道。[A1 §2.3；A2 §8.1—8.2]
- 同一源只能成功清除一次；再次清除该源视为未发现。[同上]
- 清除动作不切换测向机频道，不产生频道切换时间。[A2 §4.4、§8]

| `clear_result` | 条件 | 清除动作本身耗时 |
|---|---|---:|
| `success` | 指定频道未清除源距清除点 ≤20 米，已成功清除 | 5 秒 |
| `no_target_in_range` | 指定频道无源、源已被清除，或距离超过 20 米 | 3 秒 |

“动作本身耗时”不含到达清除点的移动时间。[A2 §8.4]

## 7. 指令、状态与计时

### 7.1 四条动作接口

| 接口 | 作用 | 额外动作参数 | 对位置/测向频道的影响 |
|---|---|---|---|
| `POST /enter` | 进入当前案例，开始计时 | 无 | 初始化原点和频道 1 |
| `POST /measure` | 到指定位置检测指定频道 | `position`、`channel` | 成功接受后更新位置及当前测向频道 |
| `POST /clear` | 到指定位置尝试清除指定频道目标 | `position`、`channel` | 成功接受后更新位置；测向频道不变 |
| `POST /exit` | 主动结束测试 | 无 | 结束；不要求返回原点 |

移动和切换频道没有独立接口，由模拟器根据前后合法动作及参数推断。所有指令共有字段为 `arena_id`、`robot_id`、`request_id`。[A1 §1—2；A2 §3、§6—9]

### 7.2 虚拟耗时

设机器狗动作前位置为 X，请求位置为 S，当前测向频道为 c，本次检测频道为 c'。距离单位为米，时间单位为秒：

\[
\Delta T_{\mathrm{measure}}=\frac{\|S-X\|}{5}
+\begin{cases}0,&c'=c,\\1,&c'\ne c,\end{cases}+5.
\]

\[
\Delta T_{\mathrm{clear}}=\frac{\|S-X\|}{5}
+\begin{cases}3,&\text{未发现},\\5,&\text{成功清除}.\end{cases}
\]

`/enter`、`/exit` 本身不增加虚拟时间。以上逐项对应 A1 §2 与 A2 §4。

按这些规则汇总，若合法动作累计移动 L 米、切换频道 n_switch 次、检测 n_measure 次、失败清除 n_fail 次、成功清除 n_success 次，则：

```text
T_virtual = L / 5 + n_switch × 1 + n_measure × 5
            + n_fail × 3 + n_success × 5  （秒）
```

这是动作计时的合计式，不是新增评价函数。重试同一已接受动作不会再次计费；被拒绝请求不生效。

### 7.3 官方计时示例

| 顺序 | 动作 | 位置 | 频道参数 | 本步耗时/秒 | 累计虚拟时间/秒 |
|---|---|---|---:|---:|---:|
| 1 | `/enter` | 原点 | 初始 1 | 0 | 0 |
| 2 | `/measure` | (300,400) | 1 | 500/5+5=105 | 105 |
| 3 | `/measure` | (300,400) | 2 | 1+5=6 | 111 |
| 4 | `/clear`，假设未发现 | (300,0) | 3 | 400/5+3=83 | 194 |
| 5 | `/measure` | (300,0) | 2 | 5 | 199 |
| 6 | `/exit` | 不变 | 无 | 0 | 199 |

第 4 步不改变测向频道，所以第 5 步无切换耗时。这是附件的说明例子，不是算法运行成果。[A1 §3；A2 §10]

### 7.4 现实时间与虚拟时间

1. 用户确认开始后，模拟器准备案例数据；准备结束后显示 5 秒倒计时。[B 附录 3；A2 §4.5]
2. 倒计时结束时打开机器狗接口，并启动 25 分钟现实测试窗口。
3. 成功 `/enter` 后开始统计程序运行时间，最多 20 分钟；与 25 分钟窗口取较早截止。窗口开始 5 分钟内进入可用足 20 分钟，较晚进入则不足。
4. `/enter` 返回 `remaining_real_duration_s`，为 0～1200 的整数，表示本局实际剩余现实秒数；不得固定按 1200 秒处理。
5. 虚拟世界上限为 100 小时，即 360000 秒。虚拟检测的 5 秒不要求程序在现实中等待 5 秒。
6. 通常从 `/enter` 到测试结束的现实时间为表格中的程序运行时间，与任务虚拟时间分别记录。
7. 到达任一截止条件后测试结束、接口关闭；截止前已完整到达并登记的唯一动作允许完成，截止时刻及之后才完整到达的请求不再执行。[A2 §4.5]

## 8. 通信基础契约

本节归纳 A2 §1.4—1.5、§5—9、§12；详细字段语法仍以原附件为准。

### 8.1 连接和请求

- 默认服务地址为 `http://127.0.0.1:2026`，只监听本机回环地址；其他电脑不能直接访问。空闲时可在模拟器中修改端口。
- 非测试期间、倒计时期间和结束后接口不开放，可能直接连接失败，没有 JSON 响应。
- 每局只允许一只与当前登录参赛队号一致的机器狗进入。
- 四接口均用 POST，路径必须精确匹配，不接受尾随斜线和查询参数。
- `Content-Type` 为 `application/json`，只允许附加 `charset=utf-8`；`Content-Encoding` 省略或为 `identity`。
- 请求体是无 BOM 的 UTF-8 JSON 对象，不允许重复键，最大 65536 字节，嵌套不超过 16 层。
- `arena_id` 必须为 ASCII 字符串 `default`。
- `robot_id` 必须逐字节匹配当前登录参赛队号，UTF-8 长度 1～64 字节；本文件不保存真实队号。
- `request_id` 为本测试会话内幂等键，UTF-8 长度 1～128 字节。两个 ID 都不允许控制字符或不可见格式字符。
- `position` 含数值 `x`、`y`，满足第 3 节范围；`channel` 为 1～20 的整数，数值恰为整数的 JSON number（如 1.0）也被接受。
- 未声明字段不会被忽略，包括 `position` 内未知字段，会返回业务拒绝。

### 8.2 响应字段

| 字段/接口 | 类型与含义 |
|---|---|
| 通用 `accepted` | boolean，是否接受动作 |
| 通用 `real_timestamp_ms` | number，响应的现实时间戳，毫秒 |
| 通用 `virtual_time_s` | number，虚拟时钟，秒；可以有小数 |
| 成功 `/enter` | 另含 `max_virtual_duration_s`（默认 360000）、`max_real_duration_s`（默认 1200）、`remaining_real_duration_s` |
| 成功 `/measure` | 另含 `measure_result`；仅 `direction` 时有 `svd_deg` |
| 成功 `/clear` | 另含 `clear_result` |
| 成功 `/exit` | 另含 `exit_reason`，主动退出为 `user_exit` |

`accepted=false` 时只返回通用三字段，没有动作结果，且 `virtual_time_s=0` 不是当前真实虚拟时刻。应保留最近一次接受响应的时间。模拟器内部按微秒累计，时钟响应最多保留 6 位小数并去除无意义末尾零。

### 8.3 串行与重试

- 不同新动作必须串行，等完整响应后才能发送下一动作；正常串行合法请求没有请求速率上限。
- 每个新动作使用新 `request_id`。仅在网络超时、连接中断等情况下重试完全相同动作时，复用原 ID 和原请求内容。
- 同 ID、同内容返回第一次完整响应，不重复移动、检测、清除、退出或推进时间。
- 同 ID 改动动作内容返回 HTTP 409；并发不同动作也会返回冲突。
- 结构错误、未知字段、`arena_id`/`robot_id` 不匹配不占用 ID，修正后可复用；已被接受的动作占用 ID。
- 同时检查 HTTP 状态和 `accepted`；处理“无法连接”和“收到 JSON”两类情况。结束后不能再用 `/exit` 查询结束原因。

### 8.4 状态码

| HTTP/业务状态 | 含义 |
|---|---|
| 200 且 `accepted=true` | 动作已执行 |
| 200 且 `accepted=false` | 业务拒绝、未知字段或身份/区域不匹配；动作未执行 |
| 400 | JSON 语法、重复键、缺失字段、类型、标识符、频道或坐标错误 |
| 404 / 405 | 路径错误 / 已知路径使用非 POST |
| 409 | ID 内容冲突或并发不同动作 |
| 413 / 415 | 请求体过大 / 请求头的内容类型或编码不支持 |
| 429 | 连接、无效流量保护，或本局幂等记录达到上限 |
| 500 | 模拟器内部错误 |

能够形成 HTTP 响应的错误返回 JSON；连接直接关闭时可能没有 HTTP 响应。

### 9.2 评价口径

题目要求问题 3 演练统计：

\[
\rho=\frac{N_{\mathrm{cleared}}}{N_{\mathrm{total}}},\qquad
\overline T=\frac{T_{\mathrm{virtual}}}{N_{\mathrm{cleared}}}.
\]

清除比例无量纲，可显示为百分比；平均定位清除时间为秒/个。分子是包括移动、切频道、检测、光学定位及清除在内的整局任务虚拟时间。问题 4 要求通过演练检验有效性，其余条件同问题 3，本项目按相同定义记录两项统计。[B 第 1—2 页]
